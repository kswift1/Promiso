# Pro Plan Launch Checklist

출시 전 Pro 플랜 관련 구현 상태를 현재 코드 기준으로 정리한 문서입니다.

## 상태 기준

- `완료`: 코드상 구현 확인
- `부분 구현`: 핵심은 있으나 체크리스트 문구와 UX 또는 범위가 다름
- `미구현`: 현재 코드/문서 기준 없음
- `제외`: 현재 범위에서 제외
- `수동 QA`: 코드만으로는 확인 불가, 실제 기기/샌드박스 검증 필요

## 1. 미구독자 → 설정 탭 구매 진입

| 항목 | 상태 | 메모 |
|------|------|------|
| 설정 탭에서 Promiso Pro 메뉴 노출 | 제외 | 원문 체크리스트에서 제외 처리됨 |
| 현재 상태 표시 (Free / Pro 활성화됨) | 제외 | Pro는 활성 플랜/관리 액션 표시. Free는 프로모션 카드가 역할을 대신하므로 별도 라벨 불필요 |
| Pro 기능 간단 요약 표시 | 제외 | 원문 체크리스트에서 제외 처리됨 |
| “Pro 알아보기” 버튼 → 페이월 연결 | 제외 | 원문 체크리스트에서 제외 처리됨 |
| 이미 구독 중이면 구독 관리 버튼 표시 | 완료 | Pro 사용자는 관리 화면으로 진입 |
| App Store 구독 관리 화면으로 이동 가능 | 완료 | `manageSubscriptionsSheet` 사용 |

## 2. 페이월

| 항목 | 상태 | 메모 |
|------|------|------|
| Pro 사용자일 경우 페이월 진입 차단 | 완료 | 설정 시트가 `ProPlan.RootView`를 사용하여 구독 상태 갱신 후 관리 화면으로 보정됨 |
| StoreKit 상품 로딩 실패 시 에러 UI 표시 | 완료 | alert + 가격 영역 inline 에러 카드 + retry 버튼 제공 |
| Intro Offer / 무료 체험 조건 체크 | 완료 | `checkIntroOfferEligibility()` 사용 |
| 구매 내역 복원 버튼 정상 작동 | 완료 | `restoreWithReceipt` + 서버 검증 경로 존재 |
| 구매 진행 중 로딩 상태 표시 및 버튼 비활성화 | 완료 | overlay + dismiss/CTA/restore 비활성화 |
| 선택된 요금제에 따라 CTA 문구 변경 | 완료 | 무료 체험 / 평생 / 일반 구독별 CTA 다름 |

## 3. Pro 기능 게이팅

| 항목 | 상태 | 메모 |
|------|------|------|
| 출발시간 계산 → 미구독자 클릭 시 페이월 | 완료 | 무료 사용자에게 CTA를 숨기는 방식으로 게이팅. Blur가 아닌 숨김이 의도된 디자인 |
| 일정 충돌 감지 → 토글 비활성 + 페이월 | 완료 | 설정 화면에서 비활성 + 탭 시 Pro 진입 |
| 날씨 정보 → Blur 처리 + Pro 안내 | 완료 | 무료 사용자에게 날씨를 숨기는 방식으로 게이팅. Blur가 아닌 숨김이 의도된 디자인 |
| AI 브리핑 → 요약만 표시 / 상세 Blur | 완료 | 요약은 보이고 상세는 blur + 업그레이드 CTA |

## 4. 구독 상태 관리

| 항목 | 상태 | 메모 |
|------|------|------|
| 앱 실행 시 restoreSubscription() 수행 | 제외 | `fetchStatus + unifiedStatusStream + Firestore 리스너`로 충분. 별도 `AppStore.sync()`는 수동 복원 버튼에서만 호출 |
| 구독 상태 관리: Free / Active / Expired / Grace Period | 완료 | `SubscriptionStatus` 모델 존재 |
| 구독 상태 변경 시 UI 자동 업데이트 | 완료 | 앱 레벨에서 상태 스트림 구독 |
| 구독 취소 시 현재 결제 기간까지 Pro 유지 | 완료 | expiration date 기준 active 상태 유지 |

## 출시 전 최종 확인

| 항목 | 상태 | 메모 |
|------|------|------|
| 페이월 진입 → 구매 → 구독 활성화 전체 플로우 테스트 | 수동 QA | 실제 샌드박스 또는 dev 빌드 확인 필요 |
| Sandbox 계정으로 구독 / 취소 / 복원 테스트 | 수동 QA | 코드상 경로는 존재하나 실기기 검증 필요 |
| 다크모드 UI 확인 | 수동 QA | 수동 확인 필요 |
| 네트워크 실패 상황 테스트 | 부분 구현 | 상품 로딩 실패는 alert + inline retry, 구매/복원 실패는 alert 처리. 실기기 시나리오 QA는 여전히 필요 |
