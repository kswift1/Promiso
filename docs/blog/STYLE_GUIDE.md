# 블로그 스타일 가이드

> "Firebase에서 Rust로: iOS 앱 서버 마이그레이션기" 시리즈의 글쓰기 기준

## 톤

- **1인칭** — "나는", "~했다". 3인칭/수동태 금지
- **~다 체** — 구어체지만 반말은 아님. "~했다", "~된다", "~인 셈이다"
- **솔직함** — 감정, 실수, 삽질을 숨기지 않는다. "엄두가 안 났다", "알고 있었지만 넘어갔다"
- **개발 일지** — 기술 문서가 아님. 의사결정 과정과 맥락을 기록하는 글

## 구조

- **훅으로 시작** — 첫 문단에서 구체적인 경험/사건/문제로 진입. 개념 설명부터 시작하지 않음
- **짧은 문단** — 2~3문장. 4문장 이상이면 나눌 수 있는지 확인
- **섹션 구분** — `---`로 큰 흐름 전환. `##`로 소주제
- **Before → Decision → After** — 기술 변경이 있는 글의 기본 뼈대
- **마무리** — 이번 편 핵심 요약 1~2문장 + 다음 편 예고

## 코드

- **코드 블록 풍부하게** — 설명보다 코드가 말하게
- **Swift 비교 박스** — Rust 문법이 처음 나오면 Swift 코드와 나란히 배치
- **주석은 "왜"만** — 코드가 뭘 하는지는 본문에서. 주석은 의도/맥락만

## 강조

- **인용 블록(`>`)** — 해당 섹션의 핵심 한 줄 요약. 남발하지 않음 (글당 2~3개)
- **굵은 글씨** — 핵심 용어 첫 등장 시, 또는 대비를 강조할 때
- **표** — 비교가 있으면 반드시 표로. 산문으로 비교하지 않음
